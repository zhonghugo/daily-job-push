# 平台规则（daily-job-push）

## 允许搜索的平台（白名单 · 可扩展）

**白名单是开放清单，遇到新渠道直接追加，不要因为不在表里就丢掉岗位。** 追加只需两步：①在下表加一行（域名 + 备注）；②在 `scripts/dedup_keys.py` 的 `DETAIL_PATTERNS` 里登记该站明细页的 URL 特征（一条正则），跑一遍回归。之后再遇到该站，`check_link` 就能自动判定明细页。

|---|---|---|

## 禁用平台（历史踩坑，勿再试）

- **拉勾网**：已关停/停摆，搜索必然空转，浪费配额
- **鱼泡网**：蓝领建筑向，与画像不匹配，表内历史记录仅 4 条且质量差 → 禁用
- **58 同城 / 赶集**：信息噪声太大，不搜

## 登录墙与授权登录

**有登录墙的平台（实测）**：BOSS直聘、智联招聘——明细页 WebFetch 只拿到安全验证/登录页；JD 正文、部分薪资字段抓不到。

**处置顺序（不许跳步）**：

1. **换渠道找同岗**（默认首选）：转载站 / 全职招聘网 / 企查查 / 公司官网常与 BOSS/智联同源，多数岗位这一步就能拿到完整 JD
2. **问用户是否授权登录**：换渠道无果且登录墙岗位**累计 ≥2 条**时，一次性问清（不逐条问）。用户同意 → 调用 `login-gated-web-extract` 技能：弹出**可见** Chrome（专用 profile），用户自己扫码/登录，零延迟后经 CDP 通道读取页面。抓到的 JD 写真实要点，来源平台仍记原平台，备注注明「经用户授权登录抓取」
   - 登录态存在专用浏览器 profile 里，**跨运行复用**——下次运行先试普通抓取，仍遇登录墙再提示「上次授权已失效，要重新登录吗」；**不要每次都重问**
   - ⚠️ 绝不截图二维码让用户扫（二维码 ~2 分钟失效，截图往返必然过期）——这是 login-gated-web-extract 的核心教训，照它的流程走
3. **用户拒绝 / 未应答（含定时自动化无人值守）**：定位链接兜底 + 要点写规范文案 `未获取到JD正文（<平台>需登录），职责要求以原始页面为准`，摘要注明「N 条因未授权登录仅定位链接」；下次交互运行时可再问一次

**安全边界**：

- 只在用户**当次明确同意**后才打开浏览器登录通道；定时自动化一律视为未授权
- 不碰用户的账号密码——登录动作全程由用户本人在可见窗口完成，技能只读登录后的页面内容
- 只抓与画像相关的招聘页面内容；登录态不用于该平台的其他操作
- 用户拒绝不算失败，照常出结果——授权是增强项，不是阻塞项

## URL 硬规则（只收明细页）

判定为**明细页**才算有效岗位：

- BOSS直聘：`zhipin.com/job_detail/<哈希>.html`
- 猎聘：`liepin.com/job/<数字或哈希>.shtml` 或 `/a/<id>.shtml` —— ⚠️ **陷阱**：`liepin.com/zhaopin*/`、`/hres/`、带 `key=` 搜索参数的都是搜索/列表页，直接丢弃
- 脉脉：`maimai.cn/web/job/...` 或 `/web/feed/detail?fid=` —— 品牌主页、社区帖、仅含关键词的搜索 URL 一律不算明细页
- 前程无忧：`51job.com/<城市代码>/job<数字>.html` 或 `jobs.51job.com/...`
- 智联：`zhaopin.com/job/PX<数字>.htm`（`sou.zhaopin.com` 是搜索页，丢弃）
- 通用判据：URL 路径含唯一 job id；带 `query=`/`key=`/`searchWord=`/`/so/`/`/list/` 的一律是搜索或列表页

`scripts/dedup_keys.py --check-link` 已内置以上规则，写作前跑一遍，别靠肉眼。

## 有效性检查（写入前）

1. 明细页 URL 判定通过
2. 用 WebFetch 开一次页面：确认岗位在招——出现「职位已关闭 / 已下架 / 停止招聘 / 已停招 / 已下线 / 已失效」任一字样即不收，抽到岗位名与标题基本一致
3. 薪资、城市至少一项可提取；都抓不到就只写链接+标题，`备注` 标"字段待补"
4. 页面 404 / 反爬验证页 → 丢弃（BOSS 常见），不硬闯

## 搜索节奏

- 每关键词每平台取前 5–8 条结果，宁缺毋滥
- 单次运行总新增 ≥ 5 条即算成功；搜不到就如实报"今日无新增"，**不要凑数**
- 同一运行内发现重复候选 → 保留先出现者（信息更全的）

## 搜索结果形态与降级链（2026-09-22 实测，必读）

当前搜索通道**不支持可靠的 `site:` 限定**——实测搜 `深圳 AI应用 招聘 site:51job.com`，返回结果里混进了 `jrzp.com`、转载站等非目标域内容。因此按"只收明细页"硬筛，很可能**一条都拿不到**。实际要按结果形态分三档处理：

| 形态 | 特征 | 处理 |
|---|---|---|
| **A. 明细页**（首选） | 见上方 URL 硬规则 | 直接入库 |
| **B. 聚合/文库页** | `wenku.51job.com`、`mwenku.51job.com`、平台内搜索结果页 | **提取线索**：抓页内的「公司 + 岗位 + 薪资 + 地点」，作为候选，再走 C 步找明细页 |
| **C. 转载站** | 应届生求职网 `yingjiesheng.com/job-*.html` 等，正文含完整 JD 且标注来源平台 | 可当明细页用（链接填转载页，`备注` 注明"转载源:前程无忧"） |

**降级链**（每档失败就退一档，别直接放弃）：

1. 搜 `{城市} {方向} 招聘` → 有明细页就直接收
2. 只有聚合页 → 页内每条岗位单独再搜一次 `{公司名} {岗位名} 招聘`，命中明细页即收
3. 命中转载站（形态 C）→ 收，并标注来源
4. 明细页补搜 ≤2 轮仍拿不到 → **`招聘链接` 不许留空**，填「定位链接」：该岗位所在平台上的**搜索页/公司职位列表页** URL，`备注` 必须写明 `定位链接（<平台>搜索页）：明细页未获取，点开为同名岗位搜索结果`（见下节）

宁可留线索，也不要因为拿不到明细页而整轮零产出——线索由人工点开补链。

## 「定位链接」是什么（2026-09-24 定）

`招聘链接` 字段**永远不为空**，但链接分两种档次，靠 `备注` 区分：

| 档次 | 链接内容 | 备注写法 |
|---|---|---|
| **明细页**（首选） | 见上方 URL 硬规则，`check_link` 判定为 `detail` | 正常备注；转载站注明来源 |
| **定位链接**（兜底） | 平台搜索页（如 `zhipin.com/web/geek/job?query=<岗位名>&city=<城市码>`、`liepin.com/zhaopin/?key=<岗位名>`、`zhaopin.com/sou/...`、公司职位列表页） | `定位链接（<平台>搜索页）：明细页未获取，点开为同名岗位搜索结果` |

规则：① 先按降级链尽力补明细页；② 补不到才降级为定位链接，**不得**把搜索页当明细页写而不加备注；③ `check_link` 判为 `search` 的候选**不得直接入库**，必须走完降级链。

## 存量链接体检（维护动作）

老记录里常混着「搜索态」链接和带跟踪参数的长 URL，肉眼看不出来。定期（或用户反馈"链接点开不对"时）跑一遍体检：

```bash
# 1) 拉全表
lark-cli base +record-list --base-token $BASE --table-id $TBL --page-size 200 --format ndjson --output check.ndjson --as user
# 2) 逐条判定（§见 dedup_keys.py 的 check_link）
python3 - <<'EOF'
import json, re, sys
sys.path.insert(0, '/Users/hugo/.workbuddy/skills/daily-job-push/scripts')
from dedup_keys import check_link
for r in map(json.loads, open('check.ndjson')):
    f = r.get('fields', r); raw = str(f.get('招聘链接',''))
    m = re.search(r'\((https?://[^)]+)\)', raw); url = m.group(1) if m else raw
    if check_link(url) != 'detail':
        print(r['record_id'], '|', f.get('岗位名称'), '|', check_link(url), '|', url[:90])
EOF
```

非 `detail` 的逐条处理：能补明细页就补（按上面的降级链）；补不到就改成定位链接 + 备注；带 `utm_*`/`pgRef`/`d_sfrom` 等跟踪参数的，**清洗成干净 URL**。
